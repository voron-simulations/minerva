# AGENTS.md

The engine-agnostic `minerva-server` library; engine adapters such as `../arma3/` depend on it by path. File paths are relative to this directory; `cargo` commands run from the repo root, `buf` from here.

## Layout

- `src/gen/` — protobuf/gRPC bindings, generated by `buf generate` and committed (`@generated`, excluded from `cargo fmt` via `include!`). Never hand-edit.
- `src/lib.rs` — re-exports; `pub mod proto` is the generated code.
- `src/state.rs` — `StateCache`: the normalized in-memory snapshot (units/groups/simulation/locations) the gRPC services read from. `Unit.group_id` is the only place group membership is recorded.
- `src/commands.rs` — domain `Command` enum and its `CommandKind`, `CommandSink` trait (implemented by engines, which declare the kinds they execute via `supported()`), `Dispatcher` (copies that set once, refuses other kinds as "not supported" before the sink sees them, tracks in-flight commands until acked or timed out). `GetSimulationInfo` reports the dispatcher's set, overwriting any `supported_commands` an adapter cached.
- `src/services/` — tonic service impls; thin wrappers over `StateCache`/`Dispatcher`.
- `src/server.rs` — `ServerConfig`, `serve()` (embed in an existing runtime), `ServerHandle::spawn()` (owns its own runtime + thread; what engine plugins use).

## Regenerating protos

```sh
buf generate   # run from server/
```

`buf.gen.yaml` reads `../proto` (the local directory, not the published BSR module), so the committed `src/gen/` must match the protos in the same commit. After any change under `proto/`, run it and commit the diff; CI's `gen-check` job runs `buf generate` fresh and fails on any diff, including newly generated files.

## Testing

- `cargo test -p minerva-server` — unit tests (`src/*.rs`) plus `tests/grpc.rs` (real `ServerHandle` over a real socket).
- `cargo llvm-cov -p minerva-server --ignore-filename-regex 'server/src/gen/'` — coverage, excluding generated code.
- `cargo bench -p minerva-server` — `benches/state.rs`; `cargo bench --workspace --no-run` just checks it compiles (CI does this, not a full run).

## Gotchas

- `ServerHandle::shutdown`/`Drop` waits for tonic's graceful connection drain, bounded by an internal grace period (`server.rs`) — without that bound, a client sharing the same single-threaded async runtime as the caller (e.g. an unadorned `#[tokio::test]`) can deadlock it, since draining needs that same thread. Integration tests use `#[tokio::test(flavor = "multi_thread")]` to avoid relying on that fallback.
